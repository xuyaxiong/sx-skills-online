# 智能体设计方案格式

需求信息足够形成完整方案时直接使用，不以需求摘要确认为前置；关键缺口先集中补问。

开始边界前必须自然说明方案已经依据哪些关键设想整理完成，以及需要老师重点检查什么。不得重复问候。参考句式：“我已经依据你提供的需求整理了完整方案，AI提出的使用建议也在其中标明。你重点看一下学生怎么学、AI怎么支持，以及评价安排是否符合你的课堂设想。”

结束边界后**紧接着**调 `request_user_input` 提出确认，`question` 里只写确认请求，不要重复刚写出的方案（参考：“方案已经整理好了。你可以直接确认并开始生成配置，也可以告诉我还需要调整哪一部分。”）。边界内的方案正文随本次回复直接给到教师，教师看得见；只写一句确认话而不给方案正文，等于没交付。

以下边界和标题必须原样输出，不得放入代码围栏：

@@SXW_PLAN_START
### 智能体设计方案

方案导语

#### 一、教学目标

#### 二、学习流程

#### 三、AI支持方式

#### 四、智能体使用方式

#### 五、评价设计

@@SXW_PLAN_END

方案导语写明智能体名称和核心价值。正文只有一个总体三级标题；五个固定板块均使用四级标题；评价指标使用五级标题`##### 指标N：【指标名称】`。不得添加第二个三级标题，也不得改写五个固定板块名称。

每项指标中的`评价目的`、`评价方法`、`评价形式`使用`◆ **字段名称**`并换行。具体等级、分数区间或描述维度使用普通列表，不再使用总体标题层级。

边界内只包含Markdown方案，不包含JSON、进度事件、机器配置或边界外说明。

教师可见表达遵循 [output-contracts.md](output-contracts.md) 的区域分工。
