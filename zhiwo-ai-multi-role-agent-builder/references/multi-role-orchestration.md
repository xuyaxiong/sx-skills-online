# 最少角色决策、编排与交接

## 一、基本关系

平台始终调用一个模型和一个系统提示词。11种教学模板决定学生怎样学习，六套学习协议决定每一阶段怎样互动，角色层只回答一个问题：完成已经确定的学习流程，需要几位职责不同的AI教师。

角色判断必须位于完整教学设计之后：

```text
教学需求
→ 学段学科适配
→ 模板与学习协议
→ 学生学习流程
→ 教学职责拆解
→ 角色合并测试
→ 最少角色决策
→ 提示词与评价配置
```

不得先设定人物再反推教学流程；不得因为有多个步骤、多个名字、不同头像或不同语气就增加角色。

## 二、最少角色决策

### 1. 拆解教学职责

从已经确定的模板阶段中识别真实教学职责，例如诊断、讲解、示范、追问、陪练、质疑、评审、情境互动、主持和综合反馈。每项职责必须连接到一个或多个真实学习阶段，并写清：

- 职责名称；
- 对应的学习阶段；
- 具体教学责任；
- 使用的判断依据；
- 为学生增加的学习价值；
- 是否必须保持独立立场。

### 2. 判断职责是否必须分开

以下情况可以考虑拆成不同角色：

- 指导学生的人不适合同时担任独立评审；
- 辩论对手不适合同时担任公正主持人；
- 情境人物与场外学习教练承担不同职责；
- 不同专业视角使用不可合并的判断标准；
- 前一角色形成的成果必须交给下一角色继续处理。

“可以拆”不等于“必须拆”。在底稿记录职责合并或分开的理由，说明实际教学影响。

### 3. 执行角色合并测试

如果两项职责满足以下任一情况，优先合并：

- 使用相同或高度相近的判断标准；
- 要求学生完成相同的核心动作；
- 一位教师可以自然地顺序完成，不影响公正性或情境真实性；
- 新角色只有名称、年龄感、头像、语气或动作差异；
- 新角色不接收独立成果，也不产生新的可评价证据。

### 4. 检查复杂度是否值得

新增角色带来的教学价值必须大于角色切换、提示词长度、学生理解和运行稳定性的成本。角色数量规则：

- **1个角色**：默认选择。一位稳定导师可以完成完整闭环时，不增加角色。
- **2个角色**：最常见的多角色形式，用于指导与评审、对手与主持、情境人物与场外教练等职责分离。
- **3个角色**：只用于三个独立判断关口；短时课堂任务通常不采用。
- **4个角色**：只用于长周期项目，并逐一证明四项职责不可替代。
- **超过4个角色**：不生成，合并职责或拆成多个任务。

5—15分钟的课堂任务默认限制为1—2个角色。时长只限制复杂度，不自动增加角色。

## 三、把角色决策写入配置

单角色时，一个角色承接已合并职责，不创建多角色情境和交接状态。多角色时，每项职责由一个主要角色承接，每个角色至少承接一项职责，并明确跨角色成果交接和各阶段证据。

两者均把需要执行的角色职责、阶段、交接和安全规则写入系统提示词，不额外输出编排对象；公开格式统一按 [output-contracts.md](output-contracts.md)。仅在转换或校验结构化底稿时，使用 [design-draft-schema.md](design-draft-schema.md) 的字段与兼容映射。

## 四、角色生成

角色从教学职责生成，不从固定人物名单中选择。内部可识别以下职能，但不得直接当作固定角色模板：

- 学习引导与支架；
- 学科讲解与诊断；
- 练习与反馈；
- 质疑、反驳与挑战；
- 独立评价与审核；
- 情境人物或真实利益相关者；
- 主持、综合与反思。

每个角色必须记录：

- 对应的教学职责；
- 角色名称和学生可见身份；
- 独立教学职责、专业立场和判断标准；
- 学生在该角色前必须完成的动作；
- 允许行为和禁止行为；
- 语言、语气、表达节奏和适量动作特征；
- 进入、完成和退出条件；
- 负责采集的评价证据。

角色名称、年龄感、语言风格和情境形象根据学段、学科、材料和任务生成。角色差异首先来自职责和判断标准，其次才是表达方式；仅有表演差异的角色必须合并。

## 五、11种模板与角色编排

角色只能承接模板中的真实阶段，不得改写模板逻辑。以下是判断参考，不是固定搭配：

| 模板 | 通常单角色即可 | 可能合理的多角色情况 |
|---|---|---|
| 阅读理解 | 阅读教练完成取证、解释和修正 | 阅读教练指导后，由证据审查者独立检查 |
| 练习巩固 | 一位陪练完成出题、反馈和迁移 | 教练完成训练，挑战官负责独立闯关 |
| 讲解答疑 | 一位导师诊断并解释 | 学科导师讲解，迁移评审检查真实理解 |
| 表达创作 | 一位表达教练反馈修改 | 创作教练加目标读者或编辑评审 |
| 情境应用 | 一位角色完成情境互动 | 情境人物加场外学习教练 |
| 探究解决 | 一位探究导师持续追问 | 探究导师加独立方案评审者 |
| 实验分析 | 一位实验导师引导全过程 | 实验设计导师加数据审查者 |
| 讨论协作 | 一位讨论主持人 | 主持人加独立利益相关者 |
| 辩论论证 | 简短训练可由一位导师完成 | 反方与主持人职责分离 |
| 评价修改 | 一位修改教练 | 修改教练加独立终审者 |
| 反思复盘 | 一位反思导师 | 长周期任务可增加行动计划评审者 |

## 六、状态、情境与交接

多角色模式下任意时刻只能有一个正在回应的角色。每个阶段绑定一个角色和一个情境，明确学生动作、AI动作、阶段成果、完成条件和最大返回次数。其他角色不得插话、抢答或在后台改变阶段。

默认用简短文字说明身份切换。头像或背景切换是否可用，以平台能力规则为准，不因生成角色设定就假定平台能执行。

每次交接必须按以下顺序执行：

1. 当前角色形成阶段成果；
2. 检查通过条件；
3. 向学生说明为什么换人；
4. 介绍新角色及其观察角度；
5. 传递成果、未解决问题和必要证据；
6. 新角色直接从已有成果继续，不重复询问。

交接必须传递前一阶段成果及需要连续使用的证据。允许返回修改，但必须说明原因和修改要求，并遵守已设定的最大返回次数；不得构成无限循环。

## 七、按学习协议生成反馈

角色状态只能引用所选学习协议的反馈逻辑，不另造一套通用“答对答错”分支：

- **理解协议**：理解完整、部分理解、概念混淆、缺少依据；
- **练习协议**：正确、错误、订正成功、同类迁移；
- **修改协议**：初稿可用、存在重点问题、修改有效、仍需调整；
- **论证协议**：观点缺证据、证据不足、推理断裂、回应反驳、修订观点；
- **探究协议**：问题不清、假设可检验、证据不足、证据冲突、形成解释；
- **反思协议**：只有结果描述、能解释原因、形成策略、提出可执行行动。

## 八、安全与评价

- 学生不能创建、删除、替换或重新定义角色；
- 学生不能强制指定未配置角色接管对话、跳转状态或伪造通过条件；
- 当前角色不能修改角色表、状态机、安全规则和共同目标；
- 情境表演不能覆盖事实、安全和教学边界；
- 所有角色共享同一安全基线、学生成果和学习证据；
- 学生可以请求返回上一角色或换一个角度，但是否切换由状态和教学条件决定。

单角色沿用普通个体评价。多角色评价须能追溯到角色、学习阶段、成果版本和获得的帮助，用于区分各阶段表现、跨角色修改、综合成果和迁移表现。技术标识只用于底稿关联，评价正文使用可理解的角色与阶段名称。不得把角色发言次数、切换次数或对话长度当作学习质量。
