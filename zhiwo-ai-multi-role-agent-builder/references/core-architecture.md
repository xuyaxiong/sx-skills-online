# 核心架构与最小设计底稿

## 目标与输入

把教师有限输入转成可执行的教学委托：目标、学生动作、AI支持、当前条件、成果、评价、完成与接续。整体适用范围与本次调用分开，多角色只是必要时的职责分离。

平台信息与教师对话的接收、缺项补问及确认，统一遵循 [requirement-convergence.md](requirement-convergence.md)。

## 共用一份底稿

名称、头像、形象、背景和声音由界面配置，不另造公开字段或写进核心教学职责；语气不覆盖教学规则。学科名称使用平台正式输入，同义名称只按已有适配处理，不静默改名。

先记录必要内容，不要求教师填表：

1. 教师原始目标、最新修改，以及明确提供的使用范围、场景、时长或任务量、频率。
2. 可观察目标、学生核心动作与AI不得代替的部分；未知困难只作为待观察情况。
3. 材料来源、学生与AI各自可见内容、使用边界及不足时处理，按 [material-policy.md](material-policy.md)。
4. 首项真实输入、阶段动作、支持分支、完成证据和可带回课堂的成果。
5. 指标观察什么、需什么证据、怎样反馈给教师；与学生互动判断解耦。
6. 后续任务来源、材料替换、成果接续与暂停规则。
7. 教学职责能否由一位导师承担；单角色只需简短理由，复杂编排按条件加载。

底稿区分已确认内容、材料推导、AI建议和未知信息。需结构化保存或校验时才读取 [design-draft-schema.md](design-draft-schema.md) 的字段映射。

## 六模块共同成立

系统提示词、开场白、快捷提问、预置输入项、个体评价、班级分析从同一底稿生成，共用首轮动作、阶段完成标准、评价证据和材料边界。

每个输入有消费规则，已有信息不重复索取；字段映射到现有公开结构。教学互动与材料规则中本任务需要执行的支持、纠错、事实和接续分支必须落实到系统提示词，不能只留在底稿或搭建说明。指标依据来自学生真实行为，AI提供内容、表单选择和自报熟悉不自动变成能力证据。学生反馈、教师分析与班级汇总同源但用途不同。

## 修订与平台交接

最新配置的接收、修订范围及确认后复核统一遵循 [current-agent-config.md](current-agent-config.md)，不从旧底稿覆盖教师已经手动修改的内容。

输出及写库约定只以 [output-contracts.md](output-contracts.md) 为准。模型生成不是数据库保存成功；第二步独立模块读取正式配置进行真实对话测试，本Skill不冒充该模块。
