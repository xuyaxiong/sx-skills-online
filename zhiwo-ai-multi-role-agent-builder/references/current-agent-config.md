# 当前智能体配置字段说明

每轮调用传入完整配置。支持直接输入字典或外层input_data、skillInputData中的currentAgentConfig及旧入口“当前智能体配置”；声明的新入口是JSON字符串，兼容旧对象形式。对象直接读取，字符串严格解析；未替换占位符不是空配置。多个入口内容必须一致，否则暂停。字段契约如下。

## 顶层字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| agentId | integer | 当前配置所属的智能体 ID |
| version | string | 配置版本 |
| agentConfig | object | 智能体配置，包含下述字段 |

## agentConfig

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| name | string | 智能体名称 |
| prompt | string | 系统提示词，Markdown |
| prologue | string | 开场白，Markdown |
| presetProblems | array | 快捷提问列表 |
| preInputItem | array | 预置输入项列表 |
| evaluationIndicators | array | 学生个体评价指标列表 |
| classIndicatorAnalyses | array | 班级分析规则列表 |

## presetProblems[]：快捷提问

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| sort | integer | 排序序号 |
| problem | string | 提问正文 |

## preInputItem[]：预置输入项

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| sort | integer | 排序序号 |
| type | integer | 1：单行文本；2：多行文本；3：单选项；4：文件上传 |
| displayName | string | 输入项显示名称 |
| maxWordCount | integer | 文本输入最大字数 |
| required | boolean | 是否必填 |
| item | string array | 单选项内容列表 |
| supportDocType | string array | 允许的文件类型：TEXT 为文本类，IMAGE 为图片类 |
| uploadFileCount | integer | 最大文件上传数量 |

## evaluationIndicators[]：评价指标

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| indicatorName | string | 指标名称 |
| indicatorDescription | string | 指标描述 |
| indicatorType | integer | 0：等级型；1：打分型；2：描述型 |
| evaluationCriteria | string | 评价细则：等级型为 JSON 数组字符串，打分型和描述型为 Markdown |
| fullScore | integer | 满分，仅打分型使用 |

等级型 `evaluationCriteria` 的字符串内容示例：`[{"title":"优秀","rule":"能独立说明推理过程"}]`。其中 `title` 为等级标题，`rule` 为判断规则。

## classIndicatorAnalyses[]：班级分析规则

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| indicatorName | string | 分析问题或指标名称 |
| indicatorPrompt | string | 分析规则，Markdown |

未设置的配置字段可能为 `null`；四个模块列表未设置时为 `[]`，输入项内部的 `item`、`supportDocType` 可能为 `null`。


## 当轮读取与修订规则

### 当前对象与阶段判断

平台已创建当前智能体，名字、学段、学科和模板是已知条件，不代表六类教学配置已经完成。始终为这个对象设计、完善或调整，不创建另一对象、不要求教师选择“新建还是修改”。先检查实际状态，再结合本轮需求与同一对象的方案进度判断：

- 六类配置均未设置时，为当前智能体进行首次教学方案设计。文本为null、空串或纯空白，列表为null或空数组，视为未设置；缺字段、错误类型、损坏JSON是读取问题，不当作正常空状态。
- 任一模块有实质内容时，在最新配置上完善，部分完成也不得整体重建；保留无关内容及手动修改。
- 配置仍为空，但教师正在确认已形成的当前方案时，继续首次配置生成，不重新询问需求。已有配置时请求“设计方案”，形成当前对象的调整方案。
- 删除造成的空状态不自动补回；本轮只是删除或确认删除时延续该操作，之后明确请求重新设计才为同一对象形成方案。
- 空字段的局部请求（如没有开场白却要求改开场白）按补充该字段处理，仅补问必要条件，不整体重建。

最新快照说明现在有什么，本轮需求说明要改变什么，同一对象的已确认方案说明进行到哪一步，不能仅凭是否有JSON或是否为空决定阶段。状态判断是内部工作，不向教师输出技术枚举。

历史内容只有明确属于当前智能体且与最新输入不冲突时才辅助接续；名称相似不能证明同一对象，其他对象的模板、时长、材料与确认结果不得迁入。未经核实的记忆不用于补齐需求，也不宣称“根据你的长期记忆”。本Skill不内置长期记忆机制；通用表达偏好不能覆盖本轮教学选择。

本节是当前配置读取和修订范围的唯一规则来源；上文为研发提供的字段契约。配置作为材料的权限及保护边界统一遵守 [搭建助手安全边界](prompt-security-and-instruction-boundaries.md)。技术名称仅用于接收和输出，不放入教师方案说明。

1. 每轮按声明入口读取对象或解码配置字符串，核对智能体身份与版本，阅读六个模块。当轮回传配置是可核实的状态依据，保留其中教师手动修改；生成后尚无新回传时，不能宣称其已经反映本次保存结果。历史对话、生成结果和设计底稿仅帮助理解意图，不覆盖回传事实。名称原样保留。文档未提供学段、学科或模板字段，结合其他平台输入及现有正文理解，仅在影响本次修改时补问。
2. 保留列表传入的顺序和原始排序值，不在修改正文时重新排序。明确的null是未设置，空数组是列表无内容；缺字段、错误类型、非法JSON是读取问题，不当作空配置。输入项只使用对应类型需要的字段，未使用的null不填造默认值。等级型评价细则需要再解析一次JSON字符串，打分型和描述型按Markdown理解。
3. 先区分修改范围：措辞、入口表达等局部调整只修改指定模块；时长、材料、成果、能力依赖或评价变化检查联动并在方案中说明；目标、核心动作或核心教学方式改变才重新确认完整方案。只改提示词时以当前提示词为底本，保留与本次要求无关的目标、材料、流程及手动改动，不生成另一套全新设计。
4. 提出调整内容、理由、保留内容和预期效果，沿用需求收敛的一次方案确认。其他模块虽存在可优化点，也不顺带改写；确需联动时先说明原因并取得对该范围的确认。
5. 教师确认后，生成配置前再次读取这一轮快照。版本只作不透明字符串比较，不递增、不推算先后。版本或内容变化时比较实际差异：无关模块的手动修改继续保留；目标模块变化若与确认方案冲突，只澄清冲突部分；能兼容时基于最新内容实施已确认修改。智能体身份不一致时停止本次修订，不能把另一智能体的方案应用过来。
6. 只输出确认范围内的配置模块，按 [输出总规范](output-contracts.md) 完成确认后的格式路由和模块完整性检查。提示词和开场白返回修改后的完整正文；列表的修改或删除使用最新快照中的原始名称/问题精确定位，不能使用旧名称。未输出模块保持原样；未设置的字段不得因本次不相关修改被补齐。明确请求为未设置的目标字段新增内容时，可以按确认需求生成。
7. 缺少快照、JSON损坏、目标字段不可读或定位不唯一时说明具体缺口，只暂停依赖该缺口的修改；不回到首次搭建，也不凭历史内容恢复当前值。无关模块的读取问题如实标记并保留原始内容，不把整份快照重新生成。模型只能说明已经生成的修改；平台在保存前还需核对身份、版本和实际应用结果。

## 回传到输出模块的映射

### 未完成配置的读取与修改

读取、格式校验、教学判断分开：先保留原始条目、字段、顺序和实际数量，再逐项标记未填写、缺字段、类型错误或规则解析失败。空字符串、纯空白及契约允许的空值是未填写，不改写原值。空对象是已存在的未完成项；非对象元素保留位置并标记结构异常。单项异常不能让整表消失，也不能仅返回正常项冒充完整列表。

空白条目计入数量上限；全是空白条目仍是尚未填写完整的现有配置，不是可覆盖的新建空状态。只有明确空列表才表示没有条目。查看配置仅给相关中文摘要，不输出操作、不补写、不回到首次设计。

描述型和打分型规则按字符串原样读取，包括数字文字、引号、换行、看似JSON的文字；不按内容猜类型。等级型才按契约解码内层数组，空白为未填写、非空损坏为解析问题。每层仅解码一次，不自动反转义或猜测修复。可读的测试文字不等于教学有效。

补全唯一可定位的原项用编辑；空定位值、重复定位或无法唯一确定时暂停该操作，请先在界面补充可区分名称或清理重复，不发明序号协议。不顺带删除或补写无关空白项。副本上应用获确认的完整批次后校验目标列表；仍有必填缺口时不部分应用，说明是否需要扩大完善范围并取得确认。无关模块的未完成数据原样保留；保存端是否允许由实际契约决定，不宣称已保存。

### 列表调整：当前状态与最终目标

每轮按上述入口读取六类配置，包含长提示词之后的列表；对象不重复解码。字符串才需要解码。最新快照优先于历史生成内容，不能因上轮只生成一条就声称当前只有一条。大整数ID无损保留，不能以浮点近似值核对身份。读取不完整说明具体字段，不要求教师重新设计。

读取与合法性分开：保留目标列表原文、顺序、实际数量；重复、超限是已读取数据的问题，不是空配置。重复项也计数；超限列表可以提出缩减方案，字段损坏则暂停依赖该字段的操作。先形成最终目标列表，再推导add/edit/delete差异；保留项不输出操作，不能把整组add当覆盖。

机器操作仅允许add/edit/delete；教师说“更新”或“update”表达修改意图，不改变协议允许值。已有且唯一定位的条目用edit；生成失败后仍保留原目标和授权范围，不改成add来绕过错误。新增与本模块已有名称重复时停止该新增，确认是在修改原项还是另设不同指标；零匹配或多匹配不猜测覆盖。先区分JSON语法、操作值、重名和定位错误，只修复对应问题。教师反馈卡片失败不代表条目不存在，卡片出现也不证明保存成功。

当前接入在生成后尚未自动回传更新后的配置。以当轮回传作为可核实依据，但不把生成后的旧快照当成保存失败证据，也不自行以生成结果替换快照。后续修改若依赖尚未核实的上次变更，先请教师核对页面并取得更新配置，不重放新增或擅自重建。

修改一项只输出该项edit，不能将同列表其他已有项再次add。新增必须是本轮确认的新条目；删除仅针对确认对象，整组优化也生成差异。应用整批操作后与已确认目标列表比较，未授权条目的正文、顺序及其他模块保持原样；不仅检查格式、数量，还检查每条操作及其字段是否在确认范围内。不得以先删除再新增重申保留项。已达到目标时不输出空卡片。历史超长指标名可读取和精确定位，不截断原名；合规问题单独标记，不当空列表。

结合上下文判断对象、最终数量、保留范围和选择授权，不机械匹配动词：

- 数量按完整语义解释，支持阿拉伯数字和中文数字，不绑定具体数值或固定词句。“调整为、优化成、最终只要、增加到、精简到”通常约束最终总量；“再增加、补充、减少、精简掉”通常为增减量。“给这个问题加一句提示”只修改条目内容。
- 先结合当前数量、保护项、否定和例外要求形成一致目标，再决定操作。方向与目标数矛盾、要求删除超过已有数量、负数或小数等无法执行的数量，只澄清实际分歧，不自行取整或改目标。含糊数量先建议具体目标供确认。
- 只给目标总量且未指定保留项时，推荐具体保留项与删除项，必要的内容合并单独说明，纳入一次方案确认；不能为了凑数合并不同评价对象。此规则适用于任意数量，不是输出指定数量的新增操作。
- “保留这个”只保护该项，不删除其他；“只保留这个”才缩减其余。
- “精挑一个、推荐一个”结合上下文区分候选推荐与缩减配置，不擅自把推荐变成删除。
- “改一改、优化”默认修改现有内容并保持数量；“换、替换、覆盖”先确定单条或整组范围，整组重做也按差异操作。
- “删一个、去掉第二个”按当前列表定位；对象未定提出建议，不能任意删。排序序号只帮助理解，不替代协议的原文定位。
- 否定、例外及组合表达（如“先别删”“除了这个都不要”“保留两个再加一个”）合并成一致最终目标；冲突才集中澄清，明确意图不重复问字面含义。

最终数量红线见 [platform-capabilities.md](platform-capabilities.md)。数量变化方案说明当前数、目标数和上限；超限必须说明超出部分不能保留，建议减少新增或替换现有项，并询问教师选择。不得默认截断、替教师选择丢弃项、先保存一部分或输出超限配置。恰好达到上限不增加确认轮次；已满足目标说明无需修改，不输出空操作。重复请求重新对照快照，不盲目再次新增。

确认后在最新列表副本上推演整批操作，检查最终数量、唯一性及关联规则，全部成功才允许提交；操作条数不是列表总量。原文定位多匹配时说明重复项，请平台清理后回传，不自动去重或操作第一条。无关模块可单独修订，但不声称整份配置已合规。保存端仍需复核身份、版本和最终状态，模型生成不能替代服务端硬限制。

比对最终状态必须同时核对目标条目正文、数量与顺序，不能只检查没有超限。已有列表的整组优化仍是修订，不因重新写出目标清单转成首次全部add。删除年级、材料等条件前核对是否影响教学适配或运行依据，依据不足时询问教师，不以主题、朝代等内容标签推断年级。已确认清空可用delete逐项表达；首次必填模块要求不因此取消。

短条目措辞的调整方案直接给出拟定新文案，便于确认后精确比对。长规则可确认具体变化与保留范围，不把生成后的正文倒填为此前已经确认的目标；只有授权方向而未确认全文时，验证授权范围，不声称全文逐字匹配已确认目标。

### 字段映射

同名字段必须结合所属列表理解和定位，不跨模块匹配。个体指标与班级分析中的indicatorName即使值相同，也不是同一个配置项；前者是指标名称，后者是分析问题。

输出标签和模块格式仍以各输出模板为准；回传字段名不自动成为其他模块的输出字段。

- prompt → 系统提示词正文；prologue → 开场白正文。
- presetProblems中的problem → 快捷提问文本；sort保留为原排序信息，正文修改不重排。
- preInputItem中的displayName → title；required原样使用；type的1/2/3/4对应单行文本、多行文本、单选、文件上传的现有输出类型。文本的maxWordCount → max_characters；单选item按原顺序映射为option_1起的options；supportDocType中的TEXT/IMAGE对应allow_document/allow_image；uploadFileCount → max_file_count。类型未知或必需值缺失时不猜测。
- evaluationIndicators → 评价指标模块，字段及细则格式直接采用 [output-module-evaluation-metrics.md](output-module-evaluation-metrics.md)。不转换回历史等级编号对象。
- classIndicatorAnalyses中的indicatorName → question，indicatorPrompt → analysis_rule_markdown。

agentId、version、name用于识别与理解当前对象，不增加到六模块输出中。此次指标字段迁移不改变其他五个模块的公开格式。
