# 六类学习协议

## 选择原则

先看学生最终成果和主要困难，再选协议。不要根据单个教学动词、角色或学科名称分类。

六类协议仍然是教学闭环的主协议。若教师的明确目的只是收集实验数据、阶段结论、作品信息或任务选择，不要求AI在当次对话中完成讲解、反馈或学习评价，可以在最接近的主协议下启用 `collection_confirmation` 执行变体；它不是第七种教学协议，也不能把本应发生的学习过程降格为填表。

## 1. 理解讲清

- 目标：理解材料、解释概念、比较关系、用自己的话讲清。
- 闭环：接触材料 → 检查理解 → 学生解释 → 反例或新情境验证。
- 最小成果：一段解释、例子、概念关系或要点。
- 不得省略：学生解释和验证。

## 2. 练习反馈

- 目标：提高正确率、形成技能、订正错误、迁移应用。
- 默认闭环：学生作答 → 具体反馈 → 有错时订正 → 按证据需要同类或变式 → 阶段小结。
- 最小成果：答案、订正、错因或迁移表现。
- 必要证据：本次技能表现。有错才订正；证据已达到约定标准时允许推进或结束，不强留学生重做。

## 3. 表达修改

- 目标：完成文字、口语、作品或其他表达并改进。
- 默认闭环：初次表达 → 对照标准反馈 → 必要修改或有依据地保留 → 说明判断。
- 最小成果：学生作品、对照标准的判断；有实质修改时保留前后稿和理由。
- 必要证据：学生表达及取舍，作品达标不为制造版本强改。

## 4. 讨论论证

- 目标：形成观点、使用依据、回应质疑、修订判断。
- 默认闭环：观点 → 依据 → 质疑或反驳 → 回应 → 有依据地修订或保留结论。
- 最小成果：有依据的观点或修订立论。
- 不得省略：依据和回应。

## 5. 探究设计

- 目标：提出问题或猜想、分析证据、设计实验或方案、检验并迭代。
- 闭环：问题或猜想 → 证据/实验/方案 → 检验评价 → 修改解释或方案。
- 最小成果：实验解释、方案初稿或迭代稿。
- 必要证据：检验及依据。检验后可修改，也可有依据地保留解释或方案。

## 6. 复盘规划

- 目标：回看证据、分析原因、总结策略、形成下一步。
- 闭环：回看表现 → 分析原因 → 总结策略 → 制定行动。
- 最小成果：错因、方法总结或具体计划。
- 不得省略：证据和下一步行动。

步骤表示常见路径，不是每轮必须走满的清单。有效动作、遇困支持、结束与接续统一遵循 [teaching-feasibility-and-interaction.md](teaching-feasibility-and-interaction.md)。

## 时长适配

| 时长 | 默认深度 |
|---|---|
| 1-5分钟 | 一个最小闭环，一个关键问题，一个成果 |
| 6-10分钟 | 一种主协议，一次反馈和一次回应/修改 |
| 11-15分钟 | 一种主协议，最多三个短阶段，形成可带回课堂的成果 |
| 16-30分钟 | 同一协议增加第二轮反馈、变式或修改 |
| 30分钟以上 | 重复主协议或串联2-3个有明确交接成果的协议 |

时间不是倒计时。接近建议时间时，不再开启长任务；完成当前小环节后允许暂停或继续。

## 轻量收集与确认变体

仅在教师明确把“可靠收集并核对学生信息”作为本次任务目标时使用：

1. 说明本次需要提交哪些字段、单位、格式或材料；
2. 一次只询问一个缺失字段，已经提供的信息不重复询问；
3. 对数值、选项、文件类型和必填项做可解释的格式校验，不擅自修改学生数据；
4. 信息齐全后完整回显，请学生确认、修改或重新提交；
5. 确认后形成结构化记录并结束本轮，不把“数据已提交”误写成“学生已经理解”；
6. 若教师还要求学生解释数据、比较证据或形成结论，收集只能作为前置阶段，随后必须回到理解、探究或反思等主协议。

不得依据常识替学生补齐缺失数据，不得把异常值自动改成“合理值”，也不得对尚未确认的数据作能力评价。
