# 个体评价与班级分析设计

声音评价按platform-capabilities.md的音频规则核对实际证据，尤其区分学生对话收到音频与评价阶段收到音频，不从转写推断声音表现。

## 评价对象与简明结果

按已确认账号归属评价：小组账号只描述该组对话中呈现的表现，不推断个人贡献或全员掌握；个人账号评价个人。共用设备不自动构成协作任务。班级分析按小组或个人统计，单位随评价对象确定，不把会话数当人数；多会话须按可靠账号标识去重，标识不足则说明实际统计范围。下文“学生数”仅适用于个人账号，小组场景统一使用组数。

方案及配置中的个体指标名称最多8个Unicode码点，汉字、字母、数字、标点均计数，不用空白填充；名称只表达中心概念，详细范围放描述。此限制不适用于班级分析问题标题。历史超长名称保留原文定位，调整后校验长度及唯一性，关联引用变化纳入确认。

从实际评价定义提炼自然名称，优先教师熟悉的学科表达；已提供的课标或量规可作依据，未核实不宣称名称来自课标。不默认套用“四字＋与＋四字”，也不机械禁用“与”或删除连接词后硬拼不同能力。一个短名称仍须对应单一中心概念，不能为满足数量要求把依据使用、反思等独立表现强行合并。名称示例不是固定词库，各学段学科按任务选择。

最终结果与后台规则分开：未达到最低证据要求一律只返回“未观察到”，不返回空值、横杠或“证据不足”。证据充分则直接返回对应等级、分数或实际描述，禁止用“正式结果”“已观察到”等状态词替代结果。描述型结果为不超过40个Unicode码点的自然短句，通常20—40字符，允许更短；只说清本指标定义下的实际表现、问题或证据边界，不凑字，不强塞建议和多栏目。规则、指标描述及班级分析全文不受40字符限制。

最低证据按实际能力表现判断，学生主动表达的等价证据也有效，不绑定固定问句。AI的解释、概括和表扬不计为学生独立理解。具体结果口径集中维护于本节，其他格式引用，不另增教师可见状态字段。

## 一、先区分评价时间范围

评价指标先分为两层，再选择等级型、打分型或描述型。

### 1. 当次任务指标

回答“学生这一次学得怎么样，老师现在可以怎样干预”。必须从本次教学需求、教学目标、任务材料、学生核心动作、最终成果和AI可见证据中生成。

生成顺序固定为：

```text
教学目标
→ 学生应完成的动作或成果
→ 对话中可见证据
→ 互斥且可观察的判定标准
→ 教师可以采取的当次行动
```

可以评价知识理解、作答正确性、技能运用、方法过程、作品质量、实验记录或本次任务中表现出的素养。不能因为某个能力名称听起来重要就加入。

### 2. 所选时间段内的多次表现

回答“老师选择的连续一至七天内，学生在多次任务中出现了哪些同口径表现”。必须读取 [longitudinal-assessment-sources.md](longitudinal-assessment-sources.md)，并记录课程标准、教师用书、校本量规或教师确认目标等来源。

一次对话只能产生本次观察事件，不能直接形成稳定的长期等级。平台可以汇总老师选定的一至七天内的多次同口径观察，但只能描述该时间段内的表现和变化，不得据此判断长期稳定能力。智能体适用范围为一课专用且没有多次分析需求时，不强行生成这类指标。

### 3. 过程、多来源、综合和长期的关系

- 平台保存完整对话、作答、修改、语音转写和图片识别内容，已经为过程性评价提供证据基础；
- 多种材料和表现属于多来源证据。如果还要求学生自评、同伴评价和教师评价，则需要相应输入，不能把AI单一评价写成多主体评价；
- 综合性不是把很多指标混成一个总分，而是围绕教学目标选择少量互补指标；
- 多次比较要求在连续一至七天的范围内保持指标定义、证据要求和汇总口径一致。

## 二、评价指标类型

评价指标分为等级型、打分型和描述型。三类完全按需选择，不要求同时出现；一套智能体可以全部使用等级型、全部使用打分型、全部使用描述型或混合使用。每个指标只选择一种主要呈现类型，避免同一含义被重复评价，指标总数最多十个。

生成指标前，先标记它的学科属性：

| 学科属性 | 评价边界 |
|---|---|
| 学科专属 | 只评价当前学科的知识、方法、技能或成果，不混入无证据的通识素养 |
| 跨学科任务 | 围绕共同成果评价整合表现；各学科存在独立教学决策时，应拆成不同指标 |
| 通识能力 | 评价可跨学科观察的表达、反思、协作或证据使用，不反推具体学科知识掌握 |

一个指标只保留一个中心概念。名称、描述、分析问题和评价规则必须指向同一件事。若两部分需要不同证据、可能出现不同结果或会引发不同教学行动，必须拆成两个指标。

### 1. 等级型

用于呈现学习情况、能力或素养所处的阶段。每一级必须有能够从学生对话中识别的行为锚点，不能只有名称。

平台可提供以下模板：

- 优秀 / 良好 / 合格 / 须努力
- 卓越 / 优秀 / 良好 / 合格 / 须努力
- 一级 / 二级 / 三级 / 四级 / 五级
- 水平一 / 水平二 / 水平三 / 水平四 / 水平五
- A / B / C / D / E
- A+ / A / B+ / B / C+ / C / D
- 新手 / 入门 / 熟练 / 精通 / 大师
- 一至五星、花、爱心或奖牌

图形模板只改变呈现，不改变等级判定规则。学生端可以显示星级等鼓励性形式，教师端应同时显示等级名称、判断依据和关键对话。

小学可以采用星、花、爱心或奖牌等图形化呈现，但教师端必须同时显示中文等级含义和判断依据。初中、高中、中职和大学默认优先使用中文等级。`A/B/C/D/E`保留为老师主动选择的可选模板，不作为默认推荐。

若任务采用四级能力锚点，可使用以下通用起点，再按学科任务改写：

| 等级 | 通用判定方向 |
|---|---|
| 须努力 | 已获得可评价的真实尝试证据，但当前未完成核心动作；包括初次作答未达到标准和帮助后仍未达到标准，按实际帮助条件描述，不能要求先接受提示才可判定，也不能仅因表达相似判低等级 |
| 合格 | 在明显提示下完成基本动作，结果或理由仍不完整 |
| 良好 | 能独立完成本阶段核心动作，理由或成果基本清楚 |
| 优秀 | 能解释依据、修正、迁移或在更复杂情境中完成 |

“未观察到”不属于任何等级。没有达到最低证据要求时直接返回“未观察到”，不能评为“须努力”。

等级型必须生成以下平台配置：

1. **等级模式**：优先选择平台已有模式作为配置起点；
2. **等级名称**：默认采用所选模式的预置名称；只有老师明确提出自定义，或修改已有自定义配置时才调整，不由模型无故改名；
3. **判断规则**：写出AI能够从学生回答、作品、修改或数据中识别的具体条件。

平台配置不单独保存或展示“等级定义”。各等级的表现边界必须直接写入对应的判断规则，避免定义与判断规则重复或产生冲突。

各等级判断规则必须互斥，并覆盖所有达到最低证据要求的有效表现。不得只写“表现优秀、表现一般”等同义反复。

核对最低证据与等级条件能否同时成立：真实首次答错且尚未获提示，不能掉入无等级可用的空档；已有证据时不能用“未观察到”掩盖规则漏项。若任务本身就是新情境应用，不能又用“没有新情境解释”排除满足最低证据的表现；需要更进一步的迁移证据时明确与本次任务区分，不假定已经安排。帮助条件用于限定判断，不代替目标表现本身。

### 2. 打分型

只用于确实需要评分的作品或表现，例如作文质量、方案质量、实验报告、论证表现或作品评价。正确率、完成率和占比原则上改用描述型，不能把百分比称为分数。

不能因为对话轮数多、回答长或完成流程而自动得分。开放性任务若缺少稳定评分标准，应改用等级型或描述型。

打分型必须生成以下平台配置：

1. **满分**：使用一至一百的正整数；
2. **实际得分**：使用零至满分之间的整数；
3. **评分方法**：从分项累加型、水平锚定型、区间判断型中选择一种；
4. **可观察标准**：说明什么学生表现对应什么分值或区间；
5. **证据不足**：未进入评价环节、材料缺失或信息不足时返回“未观察到”，得分留空；
6. **取整规则**：计算可能产生小数时，明确四舍五入或其他取整方式。

三种评分方法分别遵守：

- 分项累加型：多个得分点分别给分，各分项最高分之和必须等于满分，最终得分不超过满分；
- 水平锚定型：完整表现分别对应明确的整数分锚点，例如六十分、八十分、一百分；各水平必须互斥且可观察，不要求拆分得分点；
- 区间判断型：不同质量水平对应互不重叠的整数分区间，再依据细则在区间内取整数分；区间边界不得重叠或超过满分。

证据不足不是零分。已经进入评价环节但完全没有达到任何得分标准时，才可以依据明确规则记零分。

### 3. 描述型

用于记录学生的卡点、困难、策略、提示依赖、修改过程和下一步需要关注的内容。配置必须说明描述重点、输出长度和是否需要引用关键对话。

描述型不是自由总结。只基于实际对话证据，缺证据与结果长度遵循本文件“评价对象与简明结果”。正确率、完成率和占比的规则须写明分子、分母、时间范围、有效样本和未观察到处理，实际结果只输出整数百分比及必要的简短限定，不把规则全文塞入结果。

描述型必须生成以下平台配置：

1. **描述重点**：选择2—4项与指标直接相关的表现；
2. **评价细则**：说明从哪些学生证据识别表现，怎样区分独立表现、提示后表现和修改过程；
3. **输出结构**：直接概括本指标最关键的表现，必要时加一处问题或证据边界，不设置多栏目；
4. **长度与引用**：遵循简明结果上限，仅在确有必要且长度允许时引用短语。

描述过程事实与判断支持效果应分别设证据门槛：已观察到求助、实际困难或对应帮助时，可保留这些局部事实；没有帮助后的学生作答，只能说效果尚未观察到，不能清空已见事实，也不能判帮助无效。只有该指标完全没有达到可描述的最低证据要求时，整项返回“未观察到”。生成的判定规则、证据规则与输出要求不得互相覆盖这一范围。

描述型不得自动判断好坏，不得转换为等级或分数，不得推断性格、态度、动机或稳定的长期能力。

### 4. 类型选择

| 评价目的 | 建议类型 |
|---|---|
| 告诉学生当前处于什么水平 | 等级型 |
| 对规则明确的任务计算分数 | 打分型 |
| 统计正确率、完成率或占比 | 描述型，明确分子、分母和整数百分比 |
| 解释具体卡点、困难和过程表现 | 描述型 |
| 同时需要激励反馈和教师诊断 | 等级型或打分型作为主指标，另配描述型过程说明 |

无论采用哪种类型，都不得因为对话轮数多、句子长、完成流程或受到AI大量帮助而自动给出较好结果。

## 三、后台分析规则配置

### 1. 先确定可评价对象

根据以下五项共同选择评价指标：

1. 学段要求：学生当前应达到的认知、表达和学科发展水平；
2. 学科特点：本学科真正关注的知识、能力、思维方式或核心素养；
3. 智能体职责：该智能体在课堂中的具体介入位置和承担的学习任务；
4. 可见证据：学生在本次对话、作品、作答或修改过程中实际能够表现出来的内容。
5. 教师选择：老师确认最希望评价的表现和偏好的评价形式。

不要因为智能体有三个学习步骤就机械生成三个指标。只有当某一步对应独立、重要且可观察的学习表现时，才把它设为指标。一次短对话只能评价“本次对话中表现出的水平”，不能据此断言学生整体掌握了某一知识体系或具备稳定的长期素养。

优先选择能够支持教师后续教学决策的最小指标集合。当次任务通常推荐1—3个指标；只有智能体适用范围支持多次使用、存在正式来源且老师确认时，再增加1—2个所选时间段指标。全部指标合计不得超过十个。

- 一个指标已经覆盖核心教学目标时，只设一个；
- 两个指标能够区分关键学习表现时，不为凑数量增加第三个；
- 只有知识理解、方法运用、迁移或表达等确有不同观察证据时，才设置三个。

在最终方案确认前，必须按 [requirement-convergence.md](requirement-convergence.md) 的格式向老师展示候选指标。每项包括：

1. `【指标名称】`；
2. **评价目的**：帮助老师了解学生的什么水平、表现或困难，以及可以据此进行什么课堂或课后干预；
3. **评价方法**：把评价内容、具体评价范围和判断依据写在一起，明确评价哪种表现、在哪些材料或学习过程中评价、参考哪些学生回答、解释、修改、作品或多次记录；
4. **评价形式**：先写指标类型，再写呈现方式，例如“等级型，分为优秀、良好、合格、须努力”“打分型，满分一百分，采用水平锚定评分”“描述型，用文字概括表现和困难”。

等级型在“评价方法”中简短展示每一级的实际表现、相邻等级的关键区别，以及什么情况下还不能判断。由助理结合任务先提出建议，随原有方案请教师确认关键取舍，不另加重复确认，不固定档数或等级名称。提高标准时说清提高的具体质量，而非追求降低优秀比例。方案中解释等级含义不代表页面支持额外展示；未确认平台能力时，不承诺教师端同时显示等级、判断依据或附加说明。

分界依据任务中的准确性、解释质量、独立程度等实际表现，不能机械用术语、理由或维度数量替代质量：日常语言的准确解释同样有效，多条重复或牵强理由不自动优于一条充分解释。最高等级须有本任务可提供的表现机会。检查混合表现是否交叉或遗漏；沉默、录音故障等不能支持判断时为“未观察到”，有有效尝试呈现困难时才判相应等级。班级分析只联动确有影响的引用与解释，不因个体标准提高而无依据提高班级比例阈值。

教师可见说明不得直接使用“最低证据要求、证据边界、教学用途、结果形式”等后台字段语言。只展示“评价目的、评价方法、评价形式”。后台规则仍须保留严格的最低信息要求和证据归属，以保证评价可靠。

教师端指标用于支持人工教学判断：老师据此了解学生、识别需关注对象，并决定是否进行课堂提醒、个别辅导、分组调整、补充讲解或课后任务调整。不得把“评价目的”写成让学生在智能体中进入某个环节。智能体自身的追问、难度调节和流程切换由学生智能体提示词直接判断，与教师端指标的刷新结果解耦。

指标与完整方案统一确认后，写入最终设计底稿；不额外增加一次指标确认。不得在提示词全部生成后才第一次展示指标。

### 2. 每个指标单独配置

学生个体分析的一套配置只对应一个指标。每个指标必须完整生成以下字段：

1. **指标名称**：简短、清楚，只表达一个中心概念，能够直接出现在教师表格中；
2. **指标描述**：用一句话说明评价对象、任务范围和关键表现，不写等级或积分细则；
3. **指标类型**：等级型、打分型或描述型三选一；
4. **学科属性**：学科专属、跨学科任务或通识能力；
5. **学生学段与学科**：与平台和教案中的真实信息一致；
6. **分析问题**：用一个明确问题说明教师想了解什么，不并列询问多个维度；
7. **最低证据要求**：说明至少需要看到什么学生动作、答案、作品、修改或数据；
8. **证据不足结果**：固定为“未观察到”；
9. **类型配置**：等级模式及逐级规则、满分及积分规则，或描述重点与输出结构；
10. **学生个体分析规则**：把以上配置编译成后台可以稳定执行的完整规则。

指标名称、指标描述、分析问题、类型配置和个体规则必须指向同一含义。不得出现名称评价“推理能力”、规则却判断“知识掌握”的错位。分享范围默认“仅个人使用”；只有老师明确要求时才设为学校或全平台共享。

### 3. 编写学生个体分析规则

个体规则至少包含：

- **评价范围**：当次指标限定为本次任务；所选时间段指标只能汇总连续一至七天内的观察，不直接推断长期水平；
- **评价重点**：列出 2—4 个可以从学生发言或成果中观察的表现；
- **判定标准**：等级型给出逐级行为锚点，打分型给出得分点和不给分条件，描述型给出固定描述维度；
- **支架区分**：区分独立完成、低强度提示后完成、明显支架后完成和仅复述AI答案；
- **最低证据要求**：明确至少需要出现哪些学生动作、答案、修改或成果；未达到时统一输出“未观察到”；
- **证据归属**：只把学生主动产出的内容作为学生证据，AI提供的答案、解释或评价不能反算为学生能力；
- **输出格式**：使用稳定、简短、可供班级汇总继续解析的字段。

证据质量按内容与指标的对应关系判断，不按长短：一个数值可支持对应运算，一句准确解释可支持对应关系；只表态而无所需依据，不能补推其方法或理解。学生在提示后修正时，应同时记录初次表现、支架强度和最终表现，不能只看最终答案。任务成果与回传规则以 [teaching-feasibility-and-interaction.md](teaching-feasibility-and-interaction.md) 为准：个体规则分别写清可见成果支持的局部结论和仍未知的部分，自报完成不充当实际成果，附件不自动证明独立操作全过程。

能力锚点不得绑定首轮示例题号；新任务中满足相同目标、难度和独立性要求的表现是等价证据。区分独立表现、提示后表现、示范后应用与仅重复AI内容；示范后的新题表现不能抹去已有帮助，也不能永久否认之后符合条件的独立表现。

任务采用动态难度或跨学段分支时，依据学生实际完成的任务要求、帮助程度和成果判定，而非其所选挑战名称。难度调整不自动改变已确认的评价标准；低难度任务的成功不能证明尚未观察的高难度能力。比较学生或汇总班级时，按实际任务要求区分可比范围；跨学段标准不同的，写明各学段的行为锚点，不把不可比结果直接合成排名。必要信息缺失时只报告可支持的局部结论。

复制AI完整答案、自报“懂了”或“熟悉”不能证明独立掌握；答案相似也不能单独证明抄袭或能力差。若任务本身只要求照搬，记录该动作及未能检验的能力，不据此降低学生能力等级。根据既有最低证据要求返回“未观察到”或有证据支持的局部结果。学生端按教学流程安排新任务检查；教师端分析只评价已有证据，不假定能实时操控学生智能体。

等级型默认使用老师已经确认的中文或图形化等级模板，并为每一级写出具体行为锚点。`未观察到`是独立结果状态，不进入等级序列。

#### 个体分析规则的固定写法

个体分析规则按以下顺序编写，不调换层级，不把多个指标混在同一规则中：

1. **输入声明**：说明AI将收到一名学生与智能体的完整对话或学生成果；
2. **评价任务**：只指定当前一个指标，并限定为本次任务中的表现；
3. **观察点**：列出与学段、学科和智能体职责对应的 2—4 个可观察动作；
4. **判定规则**：写出等级、分值或描述类别的具体行为标准；
5. **证据规则**：规定证据归属、支架依赖、短回答、修正过程和“未观察到”的处理；
6. **输出要求**：按本文件简明结果口径说明实际结果和最低证据，不另造状态栏目，班级分析读取实际等级、分数或描述。

使用以下骨架生成，再把占位内容改成当前任务的具体规则：

```markdown
你将收到一名学生与【智能体名称】的完整对话记录。请根据对话，评价该学生在本次任务中表现出的【指标名称】。

【评价范围】
只评价【本次任务范围】，不推断学生长期或整体能力。

【观察重点】
1. 【可观察动作一】
2. 【可观察动作二】
3. 【可观察动作三，可按需删减】

【判定标准】
【按照所选指标类型，写出互斥、完整、可观察的等级锚点、得分点或描述类别】

【证据规则】
1. 只把学生主动说出、写出、选择、修改或完成的内容作为学生证据；
2. 区分学生初次表现、AI支架强度和学生最终表现；
3. 学生仅重复AI已经给出的答案，不视为独立掌握；
4. 回答正确但未提供本指标要求的理由时，不补推其思考过程；
5. 对话未进入对应环节或未达到最低证据要求时，只输出“未观察到”；
6. 不依据对话轮数、回答长度、语气或AI表扬判定水平。

【输出格式】
【按指标类型写明实际结果、长度与允许值，缺证据只返回未观察到】
直接输出结果，不增加状态标签、分析过程或无证据评价。
```

各类实际结果统一遵循“评价对象与简明结果”：等级只能取预设值，得分不得将缺证据自动记零分，描述只呈现实际表现；不另设结果状态、证据摘录或多栏目字段，不展示内部推演。

#### 多角色证据归属

多角色智能体的每条评价证据还必须记录`role_id`、`state_id`、`artifact_version`和`support_level`。四个字段用于区分证据来自哪个角色阶段、对应学生成果的哪个版本，以及学生是在独立完成还是获得支架后完成；它们不能替代指标本身的最低证据和判断规则。

多角色评价至少检查以下四类变化：

1. **分角色表现**：学生在不同专业立场下分别完成了什么，不把一个阶段的表现复制给所有角色；
2. **跨角色修改**：学生是否根据前一角色的反馈真正修改成果，记录修改前后版本和支架强度；
3. **综合成果**：最终成果是否整合多个角色提出的不同标准，而不是只采纳最后一个角色的意见；
4. **迁移表现**：离开原情境后，学生能否继续使用已经形成的方法或判断标准。

班级分析可以统计学生主要卡在哪个角色或状态、在哪次交接后完成了有效修改，但不得把角色发言次数、角色数量、对话长度或角色表演感当作学习质量。

### 4. 编写班级分析问题与规则

班级分析配置属于整个智能体，不强制与某一个个体指标一一对应。系统根据老师的教学与评价需求生成1—4个清楚的问题，例如“全班在哪些步骤上最容易卡住”“哪些学生需要重点关注”“学生在本次任务中采用了哪些有效策略”。

每个班级分析项必须包含：

1. **分析问题**：用老师会直接提出的问题说明想了解什么；
2. **关联指标**：列出需要读取的一个或多个已确认个体指标；如果只需归纳完整对话，可以为空；
3. **输入范围**：说明使用个体评价结果、关联对话、学生成果或其中哪些内容；
4. **分析任务**：规定要统计的分布、归纳的共性表现、需要关注的学生或教学建议；
5. **输出结构**：说明使用表格、比例、名单、文字概括、关键原话或其他教师易读形式；
6. **禁止项**：不得绕过个体规则重新评分，不得编造姓名、原因、对话或数据。

后台实际传入的其他班级分析结果可以作为输入依据，在输入范围说明所用结果；未提供时不假定存在。引用既有结果不改变原指标定义或证据边界，不要求无必要地重复生成同一张表。

### 班级统计口径

任何比例都必须在规则中明确分子、分母、单位和数据范围。

- 等级或分数分布：分子为落入该等级或分数区间的学生数，分母为获得正式结果的学生数，单位为百分比；
- 未观察到：分子为未达到最低证据要求的学生数，分母为纳入本次分析的全部学生数，单独呈现；
- 互斥错误类型：同一条有效记录只能归入一个类型时，可以计算构成占比；
- 非互斥错误类型：同一名学生或同一条记录可以出现多个类型时，使用发生率，分别说明各项分子和共同分母，并注明各项之和可能超过百分之一百；
- 人数、次数、分数和百分比使用各自单位，不能把“正确率百分之七十”写成“七十分”，也不能把次数直接当人数。

指标名称、单位和班级分析必须一致。名称含“得分”时以分为单位；名称含“正确率、完成率、占比”时以百分比呈现，不使用分数区间解释。

### 时间范围

班级分析只允许以下范围：

1. 本次课堂或本次任务；
2. 老师选择的连续一至七天。

智能体可以开放使用一个月或更久，但一次数据查看不得分析超过连续七天。只有所选一至七天内存在多次有效证据时，才能说“在所选时间段内多次出现”；不能把这类结果写成长期能力、稳定特征或整学期结论。超过七天的请求应请老师缩小或分段选择时间范围。

班级规则可以结合多个指标回答一个综合问题，但不能把多项结果混成没有解释的总分。直接读取对话时，只能归纳对话中实际出现的表现、卡点、策略和过程，不得新造一个未经确认的学生等级。

在生成班级结果前，AI必须内部检查记录缺失、重复、无法解析、人数与分布是否一致。`未观察到`单独统计，不并入低水平或需关注学生。以上检查不在正常结果中展示；只有数据异常确实影响结论时，才给出一句必要的数据范围说明。

使用以下骨架生成每个班级分析项：

```markdown
【教师问题】
【老师希望了解的一个清楚问题】

【输入范围】
读取【相关个体指标】和【需要时的关联对话或学生成果】。个体指标为空时，只归纳实际对话，不重新给学生评分。

【分析任务】
1. 【需要统计或归纳的内容】；
2. 【需要识别的共性表现、卡点、策略或学生名单】；
3. 【需要给出的教学行动建议】。

【输出结构】
【教师可见栏目的固定名称和顺序】

【禁止事项】
- 不脱离个体规则重新评分；
- 不编造学生姓名、原因、表现或数据；
- 不把“未观察到”解释为不会、薄弱或未掌握；
- 教学建议必须对应已经统计或归纳出的具体问题。
```

如果问题包含等级或分数分布，以有效个体结果为统计主表；如果问题关注共性卡点、修改过程或学生策略，可以读取关联对话进行解释。没有证据支持时，不生成泛化结论。

### 5. 五秒刷新与未观察到

平台每次刷新只需要返回两类结果：

1. `未观察到`：当前完整对话尚未达到该指标的最低证据要求；
2. 有效评价：直接返回老师选定的等级、分数或实际描述，不输出状态名称。

不设置“证据积累中”等第三种教师可见状态。后续刷新出现足够证据时，直接由“未观察到”更新为正式结果。没有新增学生证据时，平台可以保持上一结果，不必重复推断。

有效等级或分数的百分比以获得正式结果的学生数为分母；“未观察到”人数和占纳入分析学生的比例单独呈现。不要把未作答、提前退出、流程未到达与“不会”混为一类。

所选时间段指标在一次对话中只能返回“本次观察事件”或“未观察到”；平台只能在老师选定的连续一至七天内汇总多次结果，并保持同一指标和证据口径。

## 四、生成前的教学设计自检

| 指标 | 通过标准 |
|---|---|
| 目标一致 | 每个阶段直接服务已确认目标 |
| 学生先做 | AI未提前完成核心任务 |
| 支架适度 | 根据真实困难解释、示范或换方法；未提前代做用于独立检验的任务 |
| 反馈具体 | 反馈指向学生实际答案、作品或依据 |
| 反馈后行动 | 证据不足时有新增加工；已有充分证据且达标时允许结束 |
| 学科正确 | 内容、判断和评价符合学科规则 |
| 自适应 | 基础、常规和进阶学生获得不同支持 |
| 成果完整 | 达到可停留节点并形成明确成果 |
| 交回清楚 | 完成后能把成果、当前状态和下一步交回课堂或下一学习阶段 |
| 可继续 | 能在当前对话内暂停、再练或进阶；新对话需要重新提供必要成果 |
| 可评价 | 对话留下初次表现、帮助和最终结果 |

关键项“学生先做、学科正确、成果完整”任一不满足，当前配置不得作为可交付配置；先修正对应规则，再重新执行一致性校验。这里是静态设计自检，不代表目标模型已经完成对话测试。
