# 智能体调整方案格式

老师提出修改要求，Skill已经读取当前最新完整配置，但老师尚未确认调整方案时使用。此阶段不得输出修改后的正式配置。

开始前先具体回应老师的建议，并说明它会改善什么。连续对话不得重复问候。同一段只肯定一次，不连续使用“很好”“很不错”等空泛赞美。建议存在冲突或风险时，不作虚假肯定，应说明具体影响并提出可执行替代方案。

开始前以教研助理语气说明实际需要、当前情况和保留范围，不无条件赞同。语气遵循requirement-convergence.md。

结束边界后**先调 `show_content` 把上面这份调整方案的完整正文整份呈现给教师**，再调 `request_user_input` 提出一次确认，`question` 里只写确认请求，不要重复刚呈现过的调整方案（参考：“调整方案已经整理好了。你重点看一下修改范围和调整后的效果，确认没有问题后，我再更新对应配置。”）。只写一句确认话、把调整方案留在正文里，教师看不到调整方案正文。

唯一输出骨架：

@@SXW_PLAN_START
### 智能体调整方案

#### 准备调整的内容

#### 调整原因

#### 保持不变的内容

#### 调整后的预期效果

@@SXW_PLAN_END

边界内只包含Markdown。必须明确受影响模块及联动原因，但不得输出新的系统提示词、开场白、快捷提问、预置输入项、评价指标或班级分析规则正文。

教师可见表达遵循 [output-contracts.md](output-contracts.md) 的区域分工。
