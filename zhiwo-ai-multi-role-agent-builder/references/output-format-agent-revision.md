# 局部配置更新格式

只有老师明确确认“智能体调整方案”后才能使用。本阶段对应产品中的“配置调整方案”，输出实际修改后的配置项目，不再输出待确认的建议。

生成前按 [current-agent-config.md](current-agent-config.md) 复核确认当轮的最新配置和修改范围。

开始前自然承接已确认修改，说明变化与保留范围。最后一个模块结束标签后**紧接着**在回复正文里请其核对，收尾说明写调整内容已生成、本次没有涉及哪些配置；只有保存成功依据才说明已调整完成。语气遵循requirement-convergence.md。

收尾示例：“开场白的调整内容已生成，本次没有涉及其他配置。你可以在页面上核对一下是否已更新。”示例不固定套用；状态和语气统一遵循需求收敛规则，不把生成说成保存。本次更新的完整配置正文随本次回复直接给到教师，教师看得见；只写一句收尾话而不给配置正文，等于没交付。确认后的阶段切换及必需模块检查统一按输出总规范执行，预览不能代替正式模块。

唯一输出骨架：

只输出本次受影响的模块

至少输出一个受影响模块，使用各模块模板，按系统提示词、开场白、快捷提问、预置输入项、评价指标、班级分析规则的顺序排列并跳过未调整项。只改系统提示词就只输出系统提示词模块；只改开场白就只输出开场白模块。系统提示词和开场白整体覆盖；四个列表模块按新增、修订、删除规则写入。

不出现的模块表示保持原配置不变，不能表示删除。删除列表中的最后一项时，仍输出对应模块边界和一个`delete`项目；服务端处理后该列表可以为空。

包裹、外围说明和完整接收后的写入要求统一遵守 [output-contracts.md](output-contracts.md)。
