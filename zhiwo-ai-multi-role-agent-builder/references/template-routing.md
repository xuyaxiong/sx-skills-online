# 11种模板与精确路由

## 一、模板母库

本节名称与别名用于识别平台初始选择，后文资料按实际教学动作选用。推荐排序与菜单仅用于创建前的首页推荐，不在当前智能体中要求重选或补选。

| 模板ID | 教师可见名称 | 学生主要动作 |
|---|---|---|
| reading_comprehension | 阅读理解 | 阅读材料、提取信息、引用依据并解释理解 |
| practice_mastery | 练习巩固 | 作答、反馈、订正、同类或变式应用 |
| explain_teach | 讲解答疑 | 用自己的话解释，回应追问并修正理解 |
| expression_creation | 表达创作 | 形成初稿、接受反馈、修改并比较版本 |
| situated_application | 情境应用 | 在真实或模拟情境中运用知识完成任务 |
| inquiry_problem_solving | 探究解决 | 界定问题、提出想法、寻找依据、验证并形成方案 |
| experiment_analysis | 实验分析 | 提出猜想、处理数据、解释现象和异常、形成结论 |
| discussion_collaboration | 讨论协作 | 交换观点、补充信息、比较差异并形成共识 |
| debate_argumentation | 辩论论证 | 形成立场、使用证据、回应质疑并修订论证 |
| evaluation_revision | 评价修改 | 对照标准定位问题、作出判断并完成修改 |
| reflection_review | 反思复盘 | 回看证据、分析原因、总结策略并制定下一步 |

兼容规则：`explain_teach` 是稳定模板ID，不随展示名称变化。历史输入中的“讲解释疑”仅作为旧名称别名识别，进入路由后必须统一转换为“讲解答疑”，不得在任何教师可见结果中输出旧名称。

## 二、能力库、推荐关系和构建能力分开

- **能力库：** 始终是11种模板，全部允许老师选择和构建。
- **推荐关系：** 每个学段学科维护11种模板的稳定排序；前5是推荐位，其余6种是其他可选方式，不是禁用项。
- **默认排序：** 老师尚未输入具体需求时，按推荐表选出前5张卡。
- **需求重排：** 产品需要时，可以在老师输入需求后根据学生核心动作、使用场景、材料和成果重新排序；默认排序只作为并列项裁决。
- **构建能力：** 推荐顺序不改变模板母版、评价规则和测试标准。任何模板被选中后都必须进入同一构建流程。

推荐文案与排序读取 [stage-subject-template-recommendations.md](stage-subject-template-recommendations.md)，其余模板按母库顺序展示，不读取11份模板正文。搭建对话何时了解需求、提出模板建议及确认，统一遵循 [requirement-convergence.md](requirement-convergence.md)，不把首页默认推荐当作对话必经步骤。缺少专项卡片数据时使用通用来源；新写的需求例子明确标为设计示例。

构建阶段按下文的确定性构建路由执行；不能任选一个学段代替全部适用范围。

修订阶段只读取本次教学安排需要的资料和受影响规则；当前快照优先，不要求教师重新提交底稿。

## 三、三种合法选中入口

1. 老师尚未输入需求，选择默认前5中的模板。
2. 老师输入需求后，选择重新排序后的前5中的模板。
3. 老师从“查看全部”中选择未进入推荐位的模板。

以上是创建前的选择来源；老师也可以不选择情境而进入设计。进入当前对象后，按SKILL.md两类输入规则理解需求，内部资料选择不改变平台情境。完全自定义流程仍加载平台底线、学段、学科和评价规则；未选平台情境不等于必须使用自定义流程。结构化底稿的来源映射见 [design-draft-schema.md](design-draft-schema.md)。

## 四、稳定推荐规则

需求重排首先识别学生必须完成的核心动作，再判断场景、材料和成果。不得只按学科名称、卡片标题或单个关键词推荐。

匹配优先顺序：

1. 学生核心动作是否与模板一致；
2. 最终成果是否能由该模板形成；
3. 使用场景和预计时长是否能完成最小闭环；
4. 材料、设备和安全条件是否满足；
5. 当前学段学科默认排序。

相同输入和相同配置必须得到相同顺序。老师修改目标、场景、材料或成果后，才重新计算推荐。

## 五、确定性构建路由

构建时复用已经明确的学段、学科和教学意图；初始情境作设计线索，内部参考依据实际学习动作确定。信息接收与补问遵循需求收敛规则，不依赖未声明的数据表。

构建时依次组合：平台通用底线、当前模板母版、全部适用学段规则、当前学科或专业类别规则、当前教师需求和材料。存在精确的“学段×学科×模板”专项规则时，专项规则分别覆盖对应学段细节；不存在时使用前述规则组合。多学段时按跨学段资料确定任务关系；学生入口与动态教学分别读取进入配置和通用教学互动规则。不得加载相邻学科规则，也不得拒绝老师选择的非推荐模板。

材料、设备、安全和专业判断条件属于方案运行条件。条件不足时，Skill应提出补充材料、调整活动范围或交回教师判断，不能把整个模板标记为不可选。

初始情境先合理转化到当前任务。若核心动作与目标明显冲突，说明具体教学困难，建议更合适的学生动作和支持方式，经教师确认调整实际流程；不得要求更换平台情境或返回重选。

平台初始情境不随内部资料选择改变。实际教学目标或流程变化时只更新受影响底稿、配置及验证，不自动让所有未受影响成果失效。

## 六、禁止混载

- 不得把11份模板全文同时交给模型选择。
- 推荐阶段可以读取11种模板的轻量卡片配置和排序，但不得把11份模板正文同时交给模型。
- 不得仅凭模板标题让模型临时创造流程。
- 不得以角色、情境、游戏化包装替代模板学习流程。
