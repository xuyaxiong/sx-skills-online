# 六种学习范式的执行规则

## 一、与模板和后台协议的关系

六种学习范式不是新增模板，也不是课程标准的官方分类。它们用于控制同一个模板怎样组织学习、怎样提供支架、怎样形成成果以及怎样跨次接续。

构建时按以下顺序生效：

1. 11种模板确定老师选择的主要学习场景；
2. 六类后台学习协议确定一次学习闭环的基本顺序；
3. 学习范式改变对话组织、学生自主程度、成果交接和持续方式；
4. 学段、学科、材料和本次使用安排进一步约束任务难度与反馈。

每个方案只选择一个主要范式。确有必要时可以增加一个辅助范式，但不能让两套流程同时无边界运行。范式由系统根据教学目标、智能体适用范围、本次调用方式、材料和成果推荐，老师看到的是具体方案及理由，不需要先学习分类术语。

以下是组织建议，不是必须出现的额外阶段。达标结束、条件性修改与遇困支持以教学互动规则为准。

## 二、六种范式

### 1. 自主学习

- 适用：长期练习、课后学习、复盘、个人进阶和可重复使用的学伴。
- 进入：复用已明确的目标和任务；仅在本次目标确未确定时提供有限选择。是否需要学生预选，由 [interaction-entry-configuration.md](interaction-entry-configuration.md) 按教学需要判断。
- 对话：AI提供有限选择，要求学生先计划、作答或自检；表现稳定后逐步减少提示。
- 成果：本次成果、学生自评和下一步选择。
- 接续：在当前对话中支持暂停、同级再练或提高难度；新对话没有自动记忆时，由学生重新提供上次成果或薄弱点。
- 禁止：把“自主”理解为放任聊天，或由AI替学生制定全部目标和路径。

### 2. 项目学习

- 适用：跨课时项目、综合实践、工程设计、研究性学习和连续作品。
- 进入：明确本阶段任务、已有成果、角色分工和限制条件。
- 对话：按里程碑推进，每个阶段只运行一套主要协议；前一阶段成果成为下一阶段输入。
- 成果：阶段记录、项目产物、修改决定和最终版本。
- 接续：当前对话内保留阶段、版本和未解决问题；跨课堂或新对话继续时，必须重新提供前一阶段成果，不得假设自动记忆。
- 禁止：把一次短任务包装成项目学习，或在没有阶段成果时直接跳到下一阶段。

### 3. 沉浸学习

- 适用：情境应用、角色对话、职业体验、历史或社会情境和语言交流。
- 进入：用简短情境说明学生身份、任务和第一个实质动作。
- 对话：AI保持情境连贯，根据学生行动给出自然后果、信息或追问；必要时由同一导师短暂说明方法，不借此增加角色或切换身份。
- 成果：情境中的判断、表达、行动方案或任务结果。
- 接续：完成当前事件后总结知识如何在情境中被使用。
- 禁止：用冗长角色表演挤占学习任务，或因沉浸感而隐去事实和安全边界。

### 4. 探究学习

- 适用：探究解决、实验分析、开放问题、证据判断和方案验证。
- 进入：学生先提出问题、猜想、判断或初步方案。
- 对话：AI依次推动寻找证据、检验、解释和修正，不直接公布标准结论。
- 成果：探究记录、证据链、实验解释、方案或修订结论。
- 接续：未完成时保留待验证问题；完成后按目标证据和学生意愿选择新情境检验或结束。
- 禁止：虚构数据、来源或实验结果，或把开放探究退化成猜AI答案。

### 5. 关联学习

- 适用：新旧知识连接、跨学科任务、概念比较、真实应用和迁移。
- 进入：先调取学生已有知识、经验或前序成果。
- 对话：要求学生比较关系、转换表示、解释联系，并在新情境中再次使用。
- 成果：概念关系、比较说明、跨情境应用或迁移结果。
- 接续：记录已经建立的联系和仍容易混淆的边界。
- 禁止：只由AI罗列“相关知识”，学生没有亲自解释或应用。

### 6. 合作学习

- 适用：小组讨论、共同方案、同伴互评、任务分工和共识形成。
- 进入：先让每名学生独立形成初步判断，再进入交流。
- 对话：AI主持轮次、追问差异、提醒引用同伴观点、帮助整理共识和分歧。
- 成果：个人观点、同伴回应、共同结论、分工结果或待解决分歧。
- 接续：把小组成果交回全班、教师或下一任务。
- 禁止：AI冒充真实同伴观点，或只统计发言次数来判断合作质量。

## 三、与11种模板的常见组合

以下是稳定起点，不是固定一对一关系：

| 模板 | 常见主要范式 | 可选辅助范式 |
|---|---|---|
| 阅读理解 | 关联学习 | 自主学习、探究学习 |
| 练习巩固 | 自主学习 | 关联学习 |
| 讲解答疑 | 关联学习 | 自主学习 |
| 表达创作 | 自主学习 | 关联学习、项目学习 |
| 情境应用 | 沉浸学习 | 关联学习、探究学习 |
| 探究解决 | 探究学习 | 项目学习、关联学习 |
| 实验分析 | 探究学习 | 项目学习、合作学习 |
| 讨论协作 | 合作学习 | 探究学习、关联学习 |
| 辩论论证 | 合作学习 | 探究学习、沉浸学习 |
| 评价修改 | 自主学习 | 合作学习、关联学习 |
| 反思复盘 | 自主学习 | 关联学习 |

最终选择必须由本次任务和使用安排决定。相同输入使用固定的优先顺序：明确的教学目标与成果 > 智能体适用范围 > 本次调用方式 > 模板常见组合。

## 四、模板与范式不一致时的处理

先分别判断模板和范式，不用范式名称直接推翻老师选择的模板：

1. 模板看学生核心动作与最终成果；
2. 范式看学习怎样组织、支架怎样变化、成果怎样接续；
3. 后台协议看一次学习闭环内部怎样推进。

按以下三档处理：

| 状态 | 判断 | 处理 |
|---|---|---|
| `aligned` | 核心动作、成果和模板一致 | 保留模板；教师需求明确表达的范式优先于常见搭配 |
| `adaptable` | 核心动作仍属于模板，只是自主、项目、沉浸、探究、关联或合作方式不同 | 保留模板；选择一个主要范式，必要时增加一个有明确阶段边界的辅助范式 |
| `conflict` | 核心动作或成果无法由原参考流程合理形成 | 说明实际教学困难并提出新的学习动作或支持安排，请教师确认；平台初始情境保持不变，不要求换模板 |

不得用关键词机械判断冲突。必须同时检查：学生究竟做什么、最终形成什么、AI在哪一步介入、使用周期怎样组织。讨论的是实际教学安排，不要求老师重选平台情境。

`adaptable`不能加载第二份模板母版。例如选择“表达创作”并采用项目学习时，仍使用表达创作的“初稿—反馈—修改—版本成果”闭环，只把它安排到项目的多个里程碑中。选择“情境应用”并增加探究学习时，情境应用仍是主循环，探究只作用于证据查找或判断验证阶段。

`conflict`时用教师可理解的具体差异说明，不能只说“模板与范式不一致”。例如：

```text
你选择的【练习巩固】主要让学生经历“作答—反馈—订正—再次练习”；当前需求的核心是“提出猜想—设计验证—解释实验结果”。

A. 如果重点是巩固实验知识，可设计判断、订正和变式练习。
B. 如果重点是理解实验过程，建议围绕猜想、数据、异常解释和结论形成组织活动。平台初始情境不变，请确认更符合本次目标的教学安排。
```

教师选择具体教学安排后，如实说明其覆盖的学习动作，不声称一种流程完整实现互相冲突的目标。

## 五、老师可见的说明

最终方案中用两段话说明设计原理：

1. 模板如何组织学生与AI的主要互动；
2. 主要范式如何改变学生进入、推进、成果和接续方式。

不要只写“采用探究式学习”等标签。必须说明学生实际做什么、AI怎样帮助、为什么适合当前学段学科和使用安排。
